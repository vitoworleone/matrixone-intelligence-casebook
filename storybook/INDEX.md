# Storybook 导航

每个目录都是 MOI 的产品回归域。目录中的 Markdown 为可读、可审查的验收合同：在私有验证环境中以受控夹具执行，并由明确的 Pass / Fail 断言决定是否放行。

| 产品域 | 关注的产品风险 | 入口 |
|---|---|---|
| 文档智能 | 多模态内容无法被正确理解、抽取、生成或复核 | [document-intelligence/](document-intelligence/) |
| 工作流 | 输入、处理、触发与交付链路断裂或越权 | [workflow/](workflow/) |
| 数据与知识 | 数据接入、知识构建、检索与引用不可追溯 | [data-knowledge/](data-knowledge/) |
| 智能体 | 智能体调用工具、协作、输出与安全约束失效 | [agent/](agent/) |
| 评测 | 质量评测、基准数据或结论证据不可信 | [evaluation/](evaluation/) |
| 运行与治理 | 发布、监测、故障处置与服务变更不可控 | [operations/](operations/) |

## 如何使用

1. 选择与本次变更有关的产品域及所有 `required` Case。
2. 在私有环境使用受控夹具运行，逐条记录断言结果和证据位置。
3. 只有全部必过 Case 为 `pass` 才能放行；`fail`、`blocked`、`not run` 均不得视为通过。
4. 将新发现的核心风险补充为新的 Case 合同，而不是仅以人工说明替代。

## 公开边界

这里保留验收意图、输入类型、预期结果和判定口径。真实夹具、运行地址、授权信息、客户与人员信息、内部任务及原始日志均仅保存在私有验证体系中。
