## 覆盖范围

验证系统能将受控的产品需求和接口合同转换为可审核、可执行且安全的验收包，明确覆盖范围、测试数据、断言、前置条件与不确定项。

## 用户目标与风险

质量人员需要快速把需求变成可靠验收，而不是把含糊描述直接交给执行器。风险是编造接口行为、生成破坏性测试、遗漏关键约束，或把未确认假设写成通过条件。

## 受控输入

私有夹具冻结合成需求说明、接口合同、权限矩阵、风险清单和预期验收结构；不公开产品设计、接口、环境或测试脚本。

## 前置条件

- 需求和接口合同有明确版本；
- 执行环境、数据隔离、只读/写入权限和清理边界可表达；
- 验收包模板与风险分级规则已冻结。

## 产品路径

1. 输入受控需求、接口合同和环境约束。
2. 生成候选验收 Case、夹具需求、前置条件和断言。
3. 标记未确认信息、危险操作和需要人工审批的步骤。
4. 审核后导出可执行验收包。
5. 以规则检查覆盖、可追溯性与安全边界。

## 可判定验收断言

| ID | 断言 |
|---|---|
| A01 | 每项验收断言可关联到受控需求或接口合同。 |
| A02 | 输入、期望输出、失败条件、前置条件和清理要求完整明确。 |
| A03 | 未确认行为被显式标记为待澄清，不生成伪确定断言。 |
| A04 | 破坏性、越权或生产环境操作被拒绝或要求人工审批。 |
| A05 | 验收包包含核心风险、错误路径和回归优先级。 |
| A06 | 导出结构可被执行器或人工检查器解析。 |

## 预期交付物

一份包含验收 Case、受控夹具需求、断言、风险、审批和清理规则的可执行质量包。

## 运行证据

输入版本、需求到断言追溯、完整性检查、风险拦截、导出结构校验和审核记录。

## 变更影响

需求解析、合同建模、Case 生成、风险分类、审批、导出或执行器契约变更时必须重跑。

## 公开边界

不公开真实需求、接口、系统架构、测试数据、权限、脚本、环境或审核记录。
