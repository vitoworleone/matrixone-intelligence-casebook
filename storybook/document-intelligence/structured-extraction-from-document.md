# SB-DI-001｜从文档提取结构化信息

## 1. 用户目标

业务人员希望从 PDF、扫描件或图片中提取预先定义的字段，并获得可供后续系统使用的结构化 JSON；对于源文件没有提供的事实，系统不得臆造。

本 Case 控制的风险是：工作流虽然显示完成，但实际输出不符合 Schema、关键事实错误、无法追溯来源，或以看似完整的内容填补缺失事实。

## 2. 受控输入

本 Case 使用专门制作的合成工程检查记录，包含：

- 一份原生 PDF；
- 一份内容等价的扫描图片；
- 一份 JSON Schema；
- 一份人工核对过的标准答案。

Schema 至少包含记录编号、地点、测量值和条目列表等字段，并明确字段类型、嵌套关系与必填规则。正式纳入自动执行前，应在私有夹具仓库冻结文件版本与 SHA-256。

## 3. 前置条件

- 当前工作区具备读取源文件与写入结果的权限；
- 有可用的多模态提取模型；
- 有可写的隔离输出位置；
- 本次运行使用独立资源命名空间，避免与其他 Case 相互污染。

## 4. 产品路径

1. 将合成源文件放入 Catalog 可访问的位置。
2. 创建工作流并选择“结构化信息提取”能力。
3. 配置源文件、多模态模型、字段 Schema 和输出位置。
4. 保存并运行工作流。
5. 在执行详情中检查读取、提取与保存三个阶段。
6. 读取输出位置中的 JSON，并与标准答案逐字段核对。

自动化运行可使用等价的 Product SDK/API 调用，但必须产生与产品路径相同的可观察结果。

## 5. 验收断言

| ID | 断言 |
|---|---|
| A01 | 合法 Schema 可以保存；缺少必填配置时系统给出可定位的提示。 |
| A02 | PDF 与扫描图片均能进入工作流，并获得明确终态。 |
| A03 | 输出是合法 JSON，字段名、字段类型和嵌套结构符合配置 Schema。 |
| A04 | 标准答案中明确出现的事实与输出逐项一致。 |
| A05 | 源文件未提供的事实保持空值或缺失；不得生成无来源的值。 |
| A06 | 输出可关联回本次源文件和执行记录。 |
| A07 | 执行结束后清理本 Case 创建的临时资源；清理失败必须被记录为失败或阻塞。 |

## 6. 运行证据

一次 `pass` 至少需要保存以下脱敏证据：

- 夹具版本与校验结果；
- 工作流配置摘要；
- 每个阶段的终态、耗时与失败原因；
- 输出 JSON 的 Schema 校验结果；
- 字段级比对结果；
- 资源清理记录。
