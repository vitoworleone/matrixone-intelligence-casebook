# SB-OP-022｜Storybook 验收计划与问题分流

| 字段 | 值 |
|---|---|
| 状态 | `not run` |
| 门禁 | `required` |
| 夹具 | 私有夹具 `v1`；SHA-256 记录于私有验证器 |

## 覆盖范围

验证将多个核心产品旅程组织为独立验收 Case、统一问题分类和复测跟踪的运行机制。

## 用户目标和风险

产品团队需要把版本走查变成可审计的回归门禁。风险是 Case 缺少输入或断言、问题归属混乱、未复测缺陷被误标为关闭。

## 受控输入与前置条件

私有夹具包含合成 Case 清单、步骤、预期、实际观察、问题样本和分类规则；所有资源为隔离测试资源。

## 产品路径

选择必过 Case → 逐项记录输入、步骤、预期与观察 → 将异常归类为缺陷、能力缺口、体验或配置问题 → 建立复测状态。

## 明确验收断言

1. 每个 Case 都有输入、前置条件、步骤、预期、证据和状态。
2. 公共问题与单场景问题按规则分开归类。
3. `not run`、`blocked`、`fail` 不得被汇总为通过。
4. 复测结果必须链接到原始证据和同一 Case 版本。

## 预期交付物、证据与变更影响

交付验收矩阵、问题分类与复测清单。保留 Case 版本、证据摘要和断言。Case Schema、门禁、分类或报告流程变更需重跑。

## 公开边界

不公开真实环境、项目、缺陷、人员、任务、运行标识或内部讨论。
