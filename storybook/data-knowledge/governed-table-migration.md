# SB-DK-003｜授权数据迁移与表完整性对账

| 字段 | 值 |
|---|---|
| 产品域 | 数据接入 / 数据表 / 治理 |
| Case 类型 | 端到端产品回归 |
| 内容状态 | `ready` |
| 门禁级别 | `required` |
| 当前运行结果 | `not run` |

## 覆盖范围

验证在明确授权的源与目标边界内，系统能读取结构化数据、迁移到隔离目标表、保留可用的表结构与关键汇总，并登记可追溯的处理关系。

## 用户目标与风险

数据管理员需要把一张受控业务表交付给下游分析。风险是超范围复制、Schema 漂移、行丢失/重复、迁移完成却没有可核对证据。

## 受控输入

私有夹具包含合成来源表、目标 Schema、行数/主键/聚合标准答案和夹具 SHA-256。真实连接串、表名、数据记录均不公开。

## 前置条件

- 仅授权本 Case 的源读、目标写权限；
- 源/目标均处于隔离命名空间；
- 迁移窗口、冲突策略和回滚策略已定义。

## 产品路径

1. 选择已授权来源和隔离目标位置。
2. 查看来源结构、记录范围和迁移计划。
3. 运行迁移或等价数据处理工作流。
4. 在目标侧执行 Schema、行数、主键、关键汇总对账。
5. 记录来源到目标的处理关系并清理临时资源。

## 可判定验收断言

| ID | 断言 |
|---|---|
| A01 | 未授权来源或目标被拒绝，且不发生部分写入。 |
| A02 | 目标表结构符合冻结 Schema；不允许静默删列或类型降级。 |
| A03 | 行数、唯一键集合和冻结汇总与标准答案一致。 |
| A04 | 重跑按预定策略幂等或明确拒绝，不产生不可解释重复。 |
| A05 | 输入、输出和处理运行之间存在可核对的追溯关系。 |
| A06 | 中断或失败时目标处于可识别状态，能够安全清理或回滚。 |

## 预期交付物

一张通过对账的隔离目标表、迁移摘要及来源到目标的追溯记录。

## 运行证据

夹具校验、权限检查、Schema diff、行数/主键/汇总对账、重跑结果、失败处理和清理记录。

## 变更影响

连接器、导入/写表、SQL 执行、数据类型映射、血缘或权限策略变更时必须重跑。

## 公开边界

不公开真实工作区、数据库、表、连接参数、数据值、资源 ID 或原始迁移日志。
