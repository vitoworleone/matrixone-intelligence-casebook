## 覆盖范围

验证平台能够将多种受控运营数据路径（协议流、文件投递、数据库读取与人工上传）纳入同一数据资产，进行统一建模、质量检查、异常告警，并向经授权的下游交付治理后的数据及追溯信息。

## 用户目标与风险

运营数据管理员希望从分散采集变为统一治理和可观察交付。主要风险是任一接入路径成为“特殊脚本”、同一记录重复或丢失、不同模态无法关联、质量异常未被发现，或者下游取得数据却无法回溯来源。

## 受控输入

私有夹具冻结四类合成输入路径、结构化测量记录、时间序列、文件资产、元数据、异常批次及目标交付 Schema，并记录夹具版本与 SHA-256。公开仓库不保存协议数据、文件、连接或下游系统信息。

## 前置条件

- 所有连接器使用隔离测试身份，且凭据由私有密钥管理提供；
- 已建立统一的事实、维度、时序和文件资产数据模型；
- 去重、水位、失败重试、质量规则、告警规则和出仓策略均已冻结；
- 下游目标为可回收的隔离接收端。

## 产品路径

1. 配置受控流式、文件、数据库和人工上传入口，并完成连通性检查。
2. 导入基线批次后切换到增量输入，处理结构化、时序和文件资产。
3. 在 Catalog 核对统一数据模型、来源元数据和处理状态。
4. 注入冻结的质量异常，检查告警、去重、补传和处置状态。
5. 向隔离下游交付已治理数据，并核对输入到下游的追溯关系。
6. 清理连接、临时数据、告警和下游测试产物。

## 可判定验收断言

| ID | 断言 |
|---|---|
| A01 | 每种受控输入路径均能进入明确终态；不可用入口不得伪报接入成功。 |
| A02 | 同一冻结记录在重放、补传或人工重复上传后不产生不可解释重复。 |
| A03 | 结构化记录、时序数据和文件资产可通过受控关联键回到同一来源范围。 |
| A04 | 质量规则能识别冻结的缺失、时间连续性或跨资产不一致异常。 |
| A05 | 告警包含严重级别、触发原因和处置状态；重复异常遵守聚合抑制策略。 |
| A06 | 下游仅接收已授权、通过治理策略的数据，且字段/记录与冻结标准一致。 |
| A07 | 输入、处理、告警、输出和下游接收结果可形成端到端追溯。 |
| A08 | 清理失败、部分写入和网络中断均有可定位状态与恢复/回滚证据。 |

## 预期交付物

统一的受控数据资产、质量与告警摘要、隔离下游交付结果，以及完整输入到输出追溯链。

## 运行证据

夹具校验、连接状态、各路径处理计数、去重/补传检查、质量规则与告警结果、下游对账、追溯摘要和清理记录。当前 `not run` 不代表通过。

## 变更影响

连接器、上传、解析、数据模型、时序处理、文件资产、质量规则、告警、出仓、追溯、权限或恢复策略变更时必须重跑。

## 公开边界

不公开真实设备、协议、数据、组织、人员、连接地址、凭据、下游系统、资源标识、性能结果或运行日志。
