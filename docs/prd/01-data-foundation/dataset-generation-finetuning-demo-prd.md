# 数据集生成与模型精调对比 Demo 产品需求文档

## 1. 产品目标

以“上传文件 → 生成训练数据 → 模型精调 → 效果对比”的最小闭环，展示高质量数据处理对领域模型效果的影响，并帮助用户判断应选择 RAG、精调或组合方案。

## 2. 用户流程

![数据集生成与模型精调的四步体验](../assets/dataset-generation-finetuning/four-step-experience.png)

~~~text
上传文件
  ↓
解析与分块
  ↓
基于文本块生成问答对 JSONL
  ↓
使用固定模板执行参数高效微调
  ↓
同题对比基础模型与精调模型回答
~~~

界面使用固定四步进度条：上传文件、生成数据集、精调模型、效果对比。

## 3. 数据集生成

| 项目 | 规则 |
|---|---|
| 输入文件 | Markdown、PDF、Word、TXT |
| 单文件大小 | 不超过 200 MB |
| 分块 | 按标题层级、最大/最小长度切分 |
| 问题生成 | 每个文本块调用模型生成 3 个问题 |
| 答案生成 | 基于对应原文块生成答案 |
| 输出 | JSON 或 JSONL，包含 `instruction`、`input`、`output` |

```json
{
  "instruction": "根据文档回答问题",
  "input": "问题内容",
  "output": "基于原文的回答"
}
```

生成前应显示文件解析与分块状态；空文件、无法解析的文件或没有可用文本块时不得进入问答生成，并给出文件级原因。生成结果可下载，并应保留每一条样本与来源文本块的对应关系，便于检查问答质量。

## 4. 模型精调

Demo 使用预置基础模型和固定的参数高效微调模板，避免配置复杂度掩盖数据质量的影响。

| 参数 | 固定值 |
|---|---:|
| Epoch | 3 |
| Batch size | 16 |
| Learning rate | `1e-5` |
| 最大序列长度 | 32768 |
| 预热比例 | 0.05 |
| 权重衰减 | 0.01 |
| 验证步数 | 50 |
| 学习率策略 | linear |

本期不包含实时训练曲线、断点续训或最佳检查点管理。

训练只能使用已生成且通过结构校验的数据集；创建精调任务时固定记录基础模型、数据集版本和参数模板。失败时展示任务阶段及脱敏后的错误原因，并允许用户修复数据后重新发起任务。

## 5. 效果对比

同一问题在并排对话窗口中展示基础模型与精调模型的回答。本期聚焦主观结果对比，不提供自动评测分数、延迟指标或批量评测报告。

对比页应使用同一问题、同一输入上下文和固定的生成参数，避免把推理参数差异误判为精调收益；每轮问答均可追溯到对应模型版本。

## 6. RAG 与精调的选择

| 维度 | RAG | 模型精调 |
|---|---|---|
| 知识更新 | 新文档入库后可快速生效 | 通常需要重新训练 |
| 主要成本 | 检索与推理、向量索引 | GPU 训练与模型存储 |
| 可解释性 | 可展示检索来源 | 参数内化，难以定位来源 |
| 适合场景 | 内容频繁更新、预算有限、需要引用 | 稳定高频任务、输出风格或格式深度定制 |

可采用组合方案：以 RAG 保持知识更新能力，对高频核心任务进行小规模精调。

## 7. 验收标准

| 编号 | 验收项 |
|---|---|
| AC-01 | 用户可按四个固定步骤完成文件上传、数据生成、精调与对比。 |
| AC-02 | 支持规定文件格式和大小，生成符合字段约定的 JSON/JSONL。 |
| AC-03 | 每个文本块生成指定数量的问题，并以原文为依据生成答案。 |
| AC-04 | 精调使用固定参数模板并生成可用于比较的模型版本。 |
| AC-05 | 同一问题可并排展示基础模型和精调模型回答。 |
