# SQL 结果集作为业务知识需求文档

## 1. 产品目标

允许用户将经过确认的 SQL 查询结果沉淀为可检索、可解释的业务知识，使后续问答能够复用数据结论、口径、维度和来源查询，而不是每次都从零生成同类分析。

## 2. 核心对象

| 对象 | 说明 |
|---|---|
| SQL 结果集 | 一次成功执行的查询结果及其元数据快照 |
| 业务知识条目 | 基于结果集形成的可检索语义描述、口径和引用 |
| 来源查询 | 生成结果集的 SQL、参数、执行时间和数据范围 |
| 更新策略 | 快照、手动刷新或按计划重算 |

## 3. 创建业务知识

用户在成功的 SQL 查询结果中选择“保存为业务知识”，配置名称、说明、适用范围、更新策略和可见范围。系统记录：

- 结果集字段、行数、时间范围与数据版本；
- SQL 文本、参数和执行状态；
- 业务解释、指标口径、维度含义与使用限制；
- 创建时间、创建者、最后刷新时间与刷新结果。

只有成功且用户有权限访问的查询结果可以沉淀。空结果可保存为规则或记录，但必须显式标识为空结果，不能当作通用业务结论。

## 4. 检索与引用

![查询经智能体、业务知识与节点检索生成 SQL 的调用链](../assets/sql-result-business-knowledge/query-chain.png)

后续对话可将业务知识作为上下文。回答引用结果集时应展示：知识名称、数据范围、生成或刷新时间以及查看来源查询的入口。用户可以区分“业务知识中的历史快照”与“本轮实时 SQL 查询”，避免把旧数据当作实时结果。

## 5. 更新与生命周期

| 操作 | 规则 |
|---|---|
| 手动刷新 | 以保存的 SQL 与当前权限重新执行，生成新版本记录 |
| 定时刷新 | 按配置执行，失败保留上次成功版本并标识最新失败 |
| 编辑说明 | 修改业务解释与标签，不改写历史结果快照 |
| 删除 | 删除知识条目与可检索索引；保留不含敏感数据的必要审计信息 |
| 权限变化 | 失去源表权限后停止刷新和引用，并提示不可用原因 |

## 6. 安全与验收

- 结果集、SQL 和业务说明继承或收紧源数据权限，不能通过沉淀绕过行列权限。
- 不保存凭据或连接信息；对敏感字段按治理策略脱敏或禁止入库。
- 用户可创建、检索、引用、刷新和删除业务知识，且能查看数据时效与来源。
- 实时查询、历史快照、刷新失败和无权限状态均有明确区分。
