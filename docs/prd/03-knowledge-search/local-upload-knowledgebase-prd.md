# 知识库本地上传需求文档

## 1. 产品目标

本地上传让非技术用户直接在创建知识库时添加非结构化文件和表格文件，系统自动创建必要的数据资产并运行默认 RAG 数据准备流程。用户无需先手工创建数据卷、载入任务和工作流，仍可在处理后查看、编辑和追溯结果。

## 2. 创建流程

![新建知识库时在本地上传与 Catalog 选择之间切换](../assets/local-upload-knowledgebase/create-options.png)

~~~text
创建知识库 → 选择“从本地上传” → 填写名称与可选备注
→ 上传非结构化 / 结构化文件 → 创建并处理
→ 自动建立数据资产与默认处理流程 → 查看实时状态 → 对话或查看结果
~~~

## 3. 创建页面

### 3.1 数据源分类

| 分类 | 支持范围 | 限制 |
|---|---|---|
| 非结构化 | 文档、图片、音频、视频及常见办公文件 | 最多 20 个文件，单个不超过 200 MB |
| 结构化 | CSV、XLS、XLSX | 最多 20 个文件，单个不超过 200 MB |

- 页面分区展示两类上传入口；有文件后收起为继续添加入口并显示列表和已选计数。
- 列表展示类型、文件名、大小、格式与删除操作。
- 上传前校验格式、数量和单文件大小；失败文件保留在列表中并给出可单独移除或重新选择的入口，不影响其他合格文件继续创建。
- 文件名冲突需要明确处理规则：允许保留多个同名文件时以系统对象标识区分；不允许时在提交前提示改名或移除重复项。
- 名称必填且按知识库规则查重；备注可选，但在多知识库场景中建议填写以提高路由准确性。
- 高级设置默认折叠，延续知识库已有配置能力。

### 3.2 简化规则

本地上传的结构化文件自动创建新表并默认使用文件名作为表名。本流程不提供列名、类型、列描述和表描述的手工编辑；需要精细建模时，用户应使用专业数据载入或 SQL 编辑入口。

## 4. 自动数据处理

提交后系统自动：

1. 创建以知识库为边界的原始数据和处理结果存储空间；
2. 将非结构化文件写入原始数据区域，将表格文件解析为独立数据表；
3. 触发默认图文 RAG 数据准备流程，完成解析、分段、嵌入和索引；
4. 将分段与向量等结果写入处理结果区域；
5. 记录文件级与任务级状态，供详情页和后续对话使用。

以上内部映射不要求用户配置，但必须可在详情页追溯。创建失败时需说明是名称冲突、上传、表格解析、工作流还是索引失败。

处理过程按文件展示排队、处理中、成功、失败与可重试状态；创建操作不能因为某一个文件失败而丢失其他已成功处理的内容。

## 5. 状态与结果

| 状态 | 含义 |
|---|---|
| 载入中 | 文件或表正在创建 |
| 排队中 | 已保存，等待处理任务调度 |
| 处理中 | 正在解析、分段、嵌入或建立索引 |
| 处理完成 | 可用于检索和对话 |
| 处理失败 | 失败原因可查看并提供重试或删除 |

知识库列表在未完全就绪时显示处理中入口；全部文件完成后才启用对话。详情页展示文件类型、名称、大小、格式、状态和操作。

非结构化文件完成后支持左右对照查看原文件与分段结果，用户可编辑分段文本并触发索引更新；音视频预览与分段时间联动。表格文件打开表详情，展示元数据、列、统计、查询和抽样数据。

编辑后的内容以新处理版本保存，并可追溯到上传原件和触发该版本的操作。

## 6. 验收标准

- 用户可在单页完成两类文件上传、名称校验、创建和处理。
- 系统自动完成资产创建、默认流程执行与状态反馈，无需用户配置底层工作流。
- 文件级状态、失败原因、结果预览和编辑行为正确。
- 只有全部必要数据处理完成后，知识库才可进入对话。
