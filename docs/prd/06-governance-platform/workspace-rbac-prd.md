# 工作区 RBAC 权限管理产品需求文档

## 1. 产品目标

为工作区提供以角色为中心的访问控制：管理员将权限授予角色，再为用户分配角色。系统通过角色继承、对象创建者默认授权和审计记录，在保证最小权限原则的同时降低日常授权成本。

### 非目标

- 不在本期引入用户直接授权；所有业务权限均通过角色获得。
- 不在本期在数据库内核层实现独立的登录拦截机制。
- 不将角色或用户状态变更追溯性地中断已启动的任务。

## 2. 核心模型

![用户、角色与权限的基础 RBAC 关系](../assets/workspace-rbac/core-model.png)

| 概念 | 规则 |
|---|---|
| 用户 | 可被分配一个或多个角色，生效权限为各角色权限的并集。 |
| 角色 | 权限授予的最小管理单元；可拥有直接权限并继承其他角色权限。 |
| 角色继承 | 子角色继承父角色的全部有效权限；父角色变更后自动生效；禁止形成环。 |
| 对象创建者 | 创建对象时，创建者当前角色自动获得该对象的完整对象权限。 |
| 超级管理员 | 内置角色，拥有全部权限，用于平台治理和应急处理。 |

角色权限继承关系：

~~~text
用户 ──分配──> 角色 A ──继承──> 角色 B
                     │
                     └──对象权限 / 全局权限
~~~

## 3. 用户管理

### 3.1 创建用户

| 字段 | 要求 |
|---|---|
| 用户名 | 工作区内唯一。 |
| 密码 | 遵循统一密码复杂度策略。 |
| 角色 | 支持多选；至少选择一个角色。 |
| 备注 | 可选，最长 256 字符。 |

- 邮箱和手机号不作为本期用户创建字段。
- 密码确认必须一致；新密码不得与最近一次使用的密码相同。
- 工作区创建者默认成为超级管理员，且其角色不可修改、不可禁用、不可删除。

### 3.2 用户列表与操作

用户列表展示用户 ID、用户名、备注、状态、角色、创建时间和最近修改时间；支持按用户名、状态和角色筛选。

| 操作 | 行为与边界 |
|---|---|
| 修改角色 | 支持多选角色，保存后新权限即时对后续操作生效。 |
| 修改信息 | 可修改用户名和备注；用户名仍需在工作区内唯一。 |
| 修改密码 | 需校验确认密码和密码策略。 |
| 禁用 | 立即禁止后续登录与新操作，并使当前会话失效；不终止已启动任务。 |
| 启用 | 恢复该用户登录和操作权限。 |
| 删除 | 需二次确认；不删除既有任务、运行记录或审计记录。 |

普通用户默认仅可管理自己的密码和个人信息、查看自身可见日志；用户管理权限需由角色显式授予。

禁用在本期仅保证工作区应用入口和后续工作区 API 请求失效；数据库内核侧的独立客户端登录拦截依赖底层能力，不应在本需求中承诺。

## 4. 角色管理

### 4.1 创建与编辑角色

| 字段 | 要求 |
|---|---|
| 角色名 | 1–63 个字符，只允许中文、字母、数字和下划线；工作区内唯一。 |
| 权限 | 至少选择一项。 |
| 备注 | 可选，最长 256 字符。 |

角色列表展示 ID、名称、状态、备注、创建时间和最近修改时间，支持按名称和状态筛选。超级管理员角色不可编辑、禁用或删除。

### 4.2 状态与删除

- 禁用角色后，该角色不能再被分配或用于新的操作；已启动任务不受影响。
- 删除为不可逆操作，须二次确认并显示受影响用户数；有关联用户时先提示完成角色调整。
- 修改角色权限后，对后续请求即时生效；已启动任务继续按启动时上下文运行。

### 4.3 角色继承

- 支持为角色添加、移除被继承角色；继承关系禁止成环。
- 继承权限与直接授予权限需在界面中区分展示。
- 被继承角色的权限变更应自动反映到下游角色。
- 有继承关系的角色不能直接删除，需先解除关系。

## 5. 权限范围

权限按“全局权限”和“对象权限”管理。全局权限作用于工作区内同类全部对象；对象权限仅作用于被选中的对象。有效权限满足任一来源即可执行操作。

| 模块 | 典型操作 |
|---|---|
| 连接器 | 创建、查看、修改、删除、使用。 |
| 数据载入与导出 | 创建、查看、修改、暂停、恢复、重试、删除。 |
| 工作流 | 创建、运行/重试、查看/对比、停止、修改、删除。 |
| 数据资产 | 目录、库、卷、表、视图的查看、创建、修改、删除和读写。 |
| 告警 | 管理规则、通知对象与告警记录。 |
| 用户与角色 | 用户、角色、权限继承和用户标签管理。 |
| 知识库与数据发布 | 查看、使用、修改、删除、发布与订阅。 |

### 5.1 对象可见性

- 用户拥有任一子对象权限时，可看到其必要的父级路径。
- 拥有目录、库、卷、表的列表查看权限时，可查看相应层级下的对象集合；否则仅显示其有权访问的对象。
- 本期沿用现有对象可见性规则，不额外引入父级 `USAGE` 权限。

### 5.2 已知权限边界

- 工作流创建可能会自动触发首次运行；创建权限与运行权限不能完全解耦时，应在界面中明确提示。
- 默认登录角色的最小化收敛受底层能力限制，需要在后续版本继续完善。

## 6. 审计与日志

对用户、角色和权限的创建、修改、启停、删除、角色分配与继承关系变更记录审计日志，至少包含操作者、时间、目标、操作结果和失败原因。审计记录不因用户或角色删除而清除。

### 6.1 生命周期与一致性

- 创建工作区时原子创建创建者、内置超级管理员角色及其绑定关系；任一步失败不得留下可登录但无治理角色的用户。
- 删除用户或角色前，系统计算关联用户、继承关系和对象授权；需要先解除的依赖应明确列出并阻止删除。
- 权限变更对后续请求生效，已启动作业保留启动时授权上下文；审计事件须能区分直接授权、继承授权与对象创建者默认授权。

## 7. 验收要点

- 多角色用户的有效权限为并集，角色变更后后续操作立即按新权限校验。
- 禁用用户会使现有会话失效，但不终止已开始任务。
- 超级管理员和工作区创建者的保护规则生效。
- 角色继承可动态传播权限且无法形成环。
- 对象创建后，创建者角色获得完整对象权限；对象运行不受创建者后续权限变更影响。
