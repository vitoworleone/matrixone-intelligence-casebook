# 数据探索推荐问题需求文档

## 1. 产品目标

在每轮回答完成后，为用户提供三个短小、相关且可直接使用的追问建议，降低继续探索的门槛。推荐异步生成，不阻塞主回答；失败或超时则静默隐藏推荐区，保持主会话可用。

## 2. 生成架构

~~~text
用户问题 + 当前回答 + 可选最近上下文 / 数据元数据
                         ↓
               推荐问题子智能体（异步）
                         ↓
                  三个建议问题 → 前端标签
~~~

- 主回答完成后异步调用推荐子智能体。
- 输入包含当前问题、当前回答，以及可选的最近少量上下文。
- 结构化数据分析额外注入已选表结构和指标元数据，保证问题可查询且有数据支撑。
- 输出为恰好三个字符串；不写入长期消息或会话记录，仅保留在当前前端会话状态。

## 3. 推荐规则

![查询完成后的推荐追问入口](../assets/recommended-questions/follow-up-entry.png)

- 每个问题不超过 20 个中文字符或 10 个英文单词。
- 使用用户第一人称口吻；紧扣当前主题，不生成与数据范围无关的指令。
- 三个问题保持多样性：深入细节、话题内延伸、相关话题扩展。
- 数据分析场景对应下钻、横向对比、原因或洞察三个维度。
- 推荐必须可编辑，不能以自动发送替代用户确认。

## 4. 前端交互

- 推荐问题显示在回答末尾，以三个独立标签呈现。
- 点击标签将文本放入输入框，光标定位到末尾；用户可编辑后发送或按快捷方式直接发送。
- 回答生成中不展示推荐；推荐服务超时或失败时不展示错误占位。
- 刷新或重新进入会话后，不要求恢复历史推荐标签。

## 5. 验收标准

- 主回答完成后可非阻塞地得到三个建议，失败不会影响回答展示。
- 建议满足长度、相关性、第一人称和多样性约束。
- 结构化数据建议仅引用当前可用表与指标范围。
- 点击建议不会绕过用户编辑或发送确认。
