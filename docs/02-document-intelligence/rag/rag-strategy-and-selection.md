# RAG 策略与选型：是否投入、如何实施、选择什么方案

> 本文为内部调研与观点草稿。文中的 “RAG 1.0 / 1.5 / 2.0” 是便于讨论的工作分层，并非行业标准版本号。

## RAG 的定义与演进

**RAG 是什么：** 检索 → 将上下文提供给 LLM → 生成。

**演进方向：** 让生成模型在外部知识的约束下回答问题；为了提高可用性和可靠性，在检索前后增加相应的护栏。

| 层级与演进 | 代表做法 | 重点解决什么 |
| --- | --- | --- |
| **RAG 1.0** | Naive RAG、单一向量检索 + Top-k 拼接 | 提供基于检索片段的可追溯回答，但召回能力有限。 |
| **RAG 1.5** | 混合检索、元数据过滤、Cross-Encoder 重排 | 提升召回率与精排精度。 |
| **RAG 2.0** | Query Rewrite、父子块合并、HyDE、CoRAG | 提升查询表达能力与长文上下文完整性。 |
| **Agentic RAG** | LLM 作为代理进行自评、二次检索与工具调用 | 动态纠错，降低幻觉风险。 |
| **RAG + Verifier / Fact-Checker** | NLI / 检索式判别器、规则校验 | 校验事实一致性。 |

## 市场观察与关键问题

### 平台定位观察

部分 AI 应用、自动化或 RAG 平台（例如 Coze、n8n、RAGFlow、MaxKB）会将检索、LLM 生成、Agent 与可视化 Workflow 组合起来，以降低使用门槛并提供端到端能力。不同产品在部署方式、企业级治理、扩展性和运行成熟度上差异很大，不能仅因具备可视化编排或 RAG 功能就视为企业级方案。

RAGFlow 和 MaxKB 处在企业级检索基础设施（如 Zilliz Cloud、Pinecone、MongoDB Atlas Vector Search）与应用层工具（如 FastGPT，以及 GraphRAG 等方法方案）之间。是否满足企业级需求，应重点检验其治理、权限、可观测性、部署与规模化能力。

### 需要明确的问题

企业级 RAG 的底层选型不应预设为单一产品，而应在具备明确 SLA、扩展与合规能力的候选方案中评估，例如 Zilliz Cloud、Pinecone、Weaviate Cloud 与 Databricks AI Search（原 Databricks Vector Search）。

**选型维度：** 部署模式、速度、合规要求、成本、混合检索能力。

### 当前待验证的判断

- **战略空心：** “Raw Data → AI Ready Data”尚缺少与业务落地相连的闭环。
- **客户场景与 ROI 不清：** 若客户尚未厘清基础场景和价值，继续堆叠 PoC 工具难以形成差异化。
- **内部路径不清：** 企业级治理与场景结合的 AI Infra 路线仍需明确，避免概念和项目并行堆叠而缺少重点。

需要进一步回答：

1. 若做 RAG，应聚焦哪些业务场景，价值锚点是什么？
2. 若不做 RAG，“Raw Data → AI Ready Data”如何体现业务价值？
3. 当客户无法清晰表达需求时，如何判断其是否需要准确、可追溯的信息来支持业务决策？

## 结论：应做，但要选择性投入

### 选择框架

业务价值 = 信息准确性提升幅度 × 信息消耗频率 × 单位错误成本。

1. **信息准确性提升幅度：** 强解析（A）+ 高质量 RAG（B）相较于客户现状，能提升多少检索或问答准确率？
2. **信息消耗频率：** 客户在该场景下日、周、月的问答、查阅或检索次数有多少？
3. **单位错误成本：** 一次错误信息可能带来的业务损失，以及正确决策可能创造的价值是什么？

只有“三高”场景——高准确性提升潜力、高信息消耗频率、高错误成本——才应优先投入 A+B。对于低频、低错误成本的文档 FAQ 或问答机器人场景，基础解析与现成的低代码 RAG 工具通常已足够，不宜优先投入定制化能力。

### 适合投入 RAG 的场景（A+B 组合）

1. 文档量大（例如超过 1 万份），且为 PDF、扫描件、表格等复杂非结构化格式。
2. 业务频繁依赖信息查阅，例如合同、财报或政策文件。
3. 错误成本高，一次错误决策会造成明显损失。
4. 客户已认识到信息准确性会直接影响业务，并对现有检索或 FAQ 效果不满意。

## 市场分层与常见价值主张

1. **数据基础设施 / 底层数据平台**
   - 数据整合与治理闭环：通过 Lakehouse、MLflow、向量搜索和 RAG 打通统一数据与 AI 管道。
   - 数据驻留安全与 AI 内嵌：在数据所在环境中完成 AI 检索，降低不必要的 ETL 与合规风险。
   - 行业包与数据整合：将行业场景模板与数据治理能力一并交付。

2. **向量数据库 / 检索基础设施**
   - 托管服务与运营能力：按 SLA、可靠性、合规承诺和运维方式评估，例如 Pinecone。
   - 多模态与混合检索：支持多向量字段、文本与图像等多模态检索，以及私有化或自带云部署等选项，例如 Zilliz Cloud。
   - 性价比与部署灵活性：结合内存、分片、复制与高可用需求进行取舍，例如 Qdrant。

3. **RAG 平台 / AI 检索增强**
   - 通过人工参与（HITL）的标注、嵌入、评测与反馈，形成从数据到检索质量的闭环。

4. **消费级 / 轻量级 RAG**
   - MaxKB、Dify、FastGPT 等偏向低门槛 PoC 与快速验证。

5. **场景型 AI（垂直 AI / AI 应用包装）**
   - 法律、医疗、财务、数据标注等垂直领域场景。
