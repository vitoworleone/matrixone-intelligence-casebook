# 开发指南

[返回项目介绍](../README.md)

## 本地运行

使用 Node.js 22.9 或以上版本。首次安装或锁文件变化后执行 `npm ci`；把 [`.env.example`](https://github.com/Bai-009/canvas-first-workflow/blob/824397ed995dc7e1293a383bf3b90d1bc1cdf63e/.env.example) 复制为 `.env`，填写模型地址、密钥与名称，然后运行 `npm run web`。

服务默认监听 `127.0.0.1:5174`。修改端口可运行 `PORT=5175 npm run web`。实时应用的执行 Agent 和修订 Agent 默认已接入；节点生成使用真实模型，但不会执行节点描述的数据处理任务。

配置的模型服务需要支持 Chat Completions 和工具调用，规划路径使用流式响应。不同兼容服务的工具调用行为可能存在差异，已有实测记录见[观察](观察.md)。

## 构建与检查

| 命令 | 用途 |
| --- | --- |
| `npm run web` | 构建后启动本地应用 |
| `npm run build` | 生成契约类型、检查环境、编译源码、复制资源 |
| `npm run build:watch` | 首次完整构建，然后监听源码与资源变更 |
| `npm run typecheck` | 完整构建，并检查只编译、不执行的类型反例 |
| `npm test` | 构建后运行 Node.js 测试 |
| `npm run validate:fixture` | 构建后校验仓库中的计划样例 |

CI 执行类型检查、测试和计划样例校验。普通测试使用测试替身，不需要真实模型密钥。

所有应用程序源码使用 TypeScript。后端和应用模块使用 `.mts`，编译后为 `.mjs`。`prototype/plan-data.js` 是生成的演示数据，不是手写的应用程序；节点里的业务代码示例同样是数据。

浏览器与后端分别由 `tsconfig.browser.json` 和 `tsconfig.server.json` 检查：前端不获得 Node.js 环境能力，后端不获得 DOM 能力。共用契约和数据形态定义位于 `shared/`。

构建先清理 `dist/` 和 `.build-tools/`，再生成运行产物。不要直接修改这些生成目录。提示词、节点表、Schema 与静态页面也会复制到编译目录。

监听模式会更新源码与运行资源；后端程序变更后仍需重启服务。删除源码或修改 Schema 后建议重新完整构建。手动运行 Node.js 时，应使用 `dist/` 下的入口。

## 两种体验入口

**实时应用：** `npm run web`，通过浏览器访问本地 HTTP 地址。方案、构建和修订由当次模型调用产生。

**离线原型：** `npm run build` 后打开 `dist/prototype/index.html`。这一版本不调用模型：方案来自记录过的模型输出，执行画布是手写演示。它用于观察交互节奏，不用于验证执行 Agent 的行为。整个 `dist/prototype/` 目录可以独立用于演示。

更新原型方案数据：

```bash
node dist/src/prototype/build-demo-data.mjs
```

## 会话与本地数据

| 内容 | 保存位置 |
| --- | --- |
| 已发送的全局对话、规划上下文、历次方案、最新画布、配置与修订记录 | 本机 `.sessions/` |
| 生成与修订运行实录 | 本机 `.runs/` |
| 未发送的全局与节点草稿 | 当前浏览器，按会话区分 |
| 外观选择 | 当前浏览器 |
| 模型接口配置与密钥 | 服务端 `.env` |

`.sessions/`、`.runs/`、`.env` 均被 Git 忽略。可以用 `SESSION_DIR` 指定会话目录；同一目录供一个本机服务进程使用。构建不会清除会话。

会话文件写完整并同步后原子替换。服务重启恢复已提交结果；未完成的规划、构建或修订标记为中断，不自动重新调用模型。损坏存档保留原文件并报告错误，保存失败会提示重试。浏览器草稿不做跨设备同步，清除浏览器数据会丢失这些草稿。

切换会话不会停止原会话的处理。删除的会话可以从侧栏“已删除”恢复。

## 命令行入口

生成一份方案：

```bash
npm run plan -- "每天定时把新增的合同 PDF 解析出关键字段，写进数据库"
```

模型可能提交方案，也可能先询问缺失的信息。仅询问、不提交方案是合法结果。

多轮规划，保存每轮输出：

```bash
npm run plan:chat -- --save .runs/my-session
```

在 CLI 内使用 `/start` 开始构建、`/canvas` 查看画布，使用 `/note r1 文字` 添加批注（编号以实际方案为准）。CLI 的构建执行者需要显式选择：

```bash
EXECUTOR_MODULE=src/executor/executor.mjs npm run plan:chat -- --save .runs/my-session
```

想观察状态机、使用固定答复替代构建模型时：

```bash
EXECUTOR_MODULE=fixtures/doubles/fixed-executor.mjs npm run plan:chat
```

这个命令只替换执行者，规划仍使用配置的模型。固定答复用于测试控制流，不代表真实构建能力。

计划校验器也可单独运行：

```bash
node dist/src/plan/validate-plan-proposal.mjs fixtures/contract-processing.plan.json
```

规划提示词默认使用中文，`PLAN_PROMPT_LANG=en` 选择英文版本。`MODEL_REASONING` 是否可用及其取值取决于模型服务。

## 代码地图

| 目录 | 职责 |
| --- | --- |
| `web/` | 画布、节点卡片、输入、方案卡、会话管理与主题 |
| `src/web/` | HTTP 接口、事件推送与浏览器会话衔接 |
| `src/plan/` | 规划 Agent、多轮会话、方案提交与校验 |
| `src/executor/` | 按步骤构建、整图修订与工具提交 |
| `src/state-machine/` | 依赖调度、上下文组装、执行权与原子提交 |
| `src/model/` | 模型接口适配、流式组装与消息边界检查 |
| `src/storage/` | 本机会话存储 |
| `shared/` | 跨前后端类型、契约与数据形态规则 |
| `contracts/`、`nodes/`、`prompts/` | JSON Schema、节点能力目录、系统提示词 |
| `test/`、`fixtures/` | 回归测试、样例、替身与真实运行记录 |
| `prototype/` | 独立离线交互演示 |

模型接口适配会归一化部分兼容格式，例如省略的函数调用类型和对象形式的参数；不合法的 JSON 参数文本保留给 Agent 的纠错循环。缺失必要工具标识等接口问题仍会报错，不能把“兼容”理解为所有模型服务都已验证。

更完整的类型边界与迁移验证见 [TypeScript 迁移记录](TypeScript迁移.md)。首页重写前的设计约定与实现说明保存在 [2026-09-07 README 存档](archive/readme-2026-09-07.md)，其中旧进度应结合当前代码判断。
