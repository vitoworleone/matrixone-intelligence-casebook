## 最终验收结果

- 自有程序共 97 份 TypeScript 文件（含声明）；没有遗留的 JavaScript 实现，也没有内嵌 HTML 程序。`prototype/plan-data.js` 是唯一保留的 JS 文件，内容为生成数据。浏览器与 Node 实际运行编译后的 JavaScript，这不属于未迁移源码。
- 未使用 `any`、`@ts-ignore`、`@ts-nocheck` 或 `checkJs` 绕过检查；类型反例保留有意的 `@ts-expect-error`。工具依赖声明的 `skipLibCheck` 限制见 README，应用源码仍严格检查。
- 干净副本从零安装、构建和测试；预先放置的旧 `.js`／`.mjs` 产物在完整构建后消失，源文件和私有目录不受影响。新增清理与资源边界测试也在最低支持版本 Node 22.9.0 通过。
- 真实命令入口 `plan`、`plan:chat`（提交方案、开始、查看画布、保存）和 `executor:step`（单步与保存）全部使用本地固定模型验收，没有调用真实供应商。描述导出与原型数据生成也已验证；未接入真实处理库。
- 浏览器已验证会话新建／改名／删除恢复、主题与刷新、两步工作流生成、参数保存、缩放、节点和会话栏的八种预览状态；主原型六步播放、方案卡展开收起与后续修改正常。
- 最终 `npm run web` 在原 5174 地址启动，旧 PDF 五节点工作流刷新恢复。3 个活动会话和 2 个已删除会话的清单在重启前后完全一致；191 份已有会话、配置、运行记录文件的哈希不变。
- 各阶段已分别进行代码 review 并提交叠加 PR；最终 review 核对了构建清理范围、资源复制边界、运行入口及上述证据。PR 保持待合并，不自动合并。

## 保留的边界

这是语言和工程组织的迁移；数据处理仍是演示。外部数据的运行时检查与工作流业务门禁仍然必需，TypeScript 不替代它们。监听模式更新源码；删除源码、修改 Schema 或静态资源后需完整构建，后端更改后需重启服务。
